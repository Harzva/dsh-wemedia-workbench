# Project collaboration

- Read `README.md` and `docs/ai-assisted-workflow.md` for the public capability and content-disclosure contract.
- Articles should disclose actual AI assistance. Exact model attribution is optional, including for drafts that never reached a platform. Never invent human review or successful delivery.
- Keep minimal private revision, approval, job and target evidence for recovery and duplicate prevention. Do not delete existing records merely because a model-attribution table is unnecessary.
- Distill reusable failures and fixes into `docs/workflow-lessons.md`, then focused tests or code when supported by evidence. Do not publish private execution histories or account data.
- Preserve the shared application service and native approvals. No alternate CLI, HTTP mutation or ledger edit may bypass those boundaries.
- Do not build into a source checkout loaded by a running DSH instance. Use an independent checkout and an isolated, account-free profile for release verification.
- Public docs use the allowlist in `.gitignore`. Audit the exact Git tree and package contents before pushing; ignored local documents must stay local.
- Source publication, installable release, account verification and formal publication are separate milestones. Report only the evidence actually obtained.
