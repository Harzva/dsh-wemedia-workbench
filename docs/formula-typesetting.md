# 可追溯的公式排版

公式应同时表达正确的数学关系和足够清晰的读者说明。排版成功不代表事实
正确；图片尺寸、来源、当前修订和审阅记录必须分别核验。

## 本地工具

[render-formulas.py](../scripts/render-formulas.py) 使用 Matplotlib 的公共
MathText API 和 STIX 数学字体，输出白底 3 倍分辨率 PNG。脚本依赖另行安装
的 Matplotlib、NumPy、Pillow；不启动外部 TeX，不调用浏览器或网络，不下载
字体或模型，也不会向 DSH 登记修订或证据。

输入是 `formulas` 数组，每项包含唯一 `basename`、ASCII LaTeX `lines`、
`source`（公共 HTTPS URL、PDF 页码、章节）和 `alt`。LaTeX 不带 `$` 分隔符；
中文解释放在文章正文。每个输出记录公式行、来源位置、PNG SHA、渲染版本及
显示尺寸。完整示例见 [PTC 工作流](ptc-workflows.md#本地公式-png)。

输出目录已存在时拒绝覆盖。过长的公式应在数学语义允许的位置显式分行，
不能为了塞进卡片无限缩小字号。脚本会拒绝超出预定宽度的表达式。

## 编辑检查

- 对照原论文确认上下标、条件概率、求和范围、不等号和括号，而非只看 LaTeX 是否可渲染。
- 保留原论文式号；自行概括的关系或选择步骤不能伪造原编号。
- 在公式附近说明用途、符号和结论边界，区分启发式评分、概率和实际执行条件。
- 原图或原表细字过小时补充准确的正文说明，不宣称所有细字在手机上都清晰。

## 进入文章工作流

1. 校对输入公式和原始来源。
2. 运行本地脚本，查看生成 PNG 和来源映射。
3. 通过原生保存流程将素材绑定新修订；不改写只读原稿。
4. 重新登记受影响的事实、编辑、图片与公式审阅。
5. 实际查看该修订的手机全文预览，检查素材加载、公式边界和水平溢出。
6. 登记真实截图后再预检、审批和提交目标渠道。

工作台预览不是微信客户端实机截图。旧修订的图片或报告不能直接标作新修订
的通过证据。私有文章标识、Job、target、账号状态和原始验收截图不随本通用
文档公开。
